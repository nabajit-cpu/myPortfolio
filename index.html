Case study

Supplier sync → CMS → booking funnel (Paytm Hotels).

Hotel content & mappings pipeline

Incremental supplier sync, event-driven ingest, and a multi-service booking path — built for safe rollouts and clear ownership between teams.

Read the flow
  1. Sync (Go) — Scheduled and on-demand jobs discover new, updated, and removed hotel mappings; MySQL tracks locks, cursors, and run state; Kafka carries fetch work and per-hotel payloads.
  2. CMS (Java) — Phase A ingests provider data, resolves canonical hotel IDs, stores split raw content in MongoDB; Phase B merges supplier views, fills curated gaps, emits lifecycle updates for search and recommendation.
  3. Booking funnel — BFF-facing APIs over search, availability, room rates, and cart/review; Spring Boot services, Redis caching, supplier integrations behind gateway adapters.

Takeaway: idempotent consumers, feature flags, and publish-before-persist ordering keep downstream systems consistent under incremental sync.
